# US3 真實寫回人工步驟 — NOT RUN

記錄日期：2026-11-18；分支 codex/google-sheets-integration。本檔為操作指引，**不是人工通過紀錄**。使用者先前回報 Test-A 讀取六題／一工作表／第4題 WAITING／UNKNOWN，不能推定可寫或本次寫回已驗證。T003／T004維持未勾選。

1. 依 quickstart.md 完成專用 Google Cloud／Sheets API／Service Account 設定；key 放 repository 外，只設後端 GOOGLE_APPLICATION_CREDENTIALS，不能貼給代理、前端、日誌或 Git。每份專用表分別分享給服務帳號 Editor，檢查答案格保護範圍。系統顯示 UNKNOWN 不是權限保證。
2. 使用專用範本副本（如 ClassroomQuiz-Test-A 的副本），確認所有支援 GRID（含隱藏）的完整 {{Q1}}..{{QN}}，不要用真實學生資料。先保存非答案值、公式定義、整格格式、合併與結構供比較。活動期間所有協作者停止編輯原表（A-04）；前置讀取加寫入沒有 Google CAS 鎖。
3. 依 quickstart.md 以既有 npm scripts 啟動前後端。老師登入，**先設有效組數，再貼本份 Sheets URL**；確認題數、支援分頁與權限提示。學生使用不同瀏覽器身分加入，不需 Google 帳號。更換來源須新的活動；本版無來源切換或自動重建功能。
4. 若仍是先前第4題 WAITING 的活動，可以使用它的既有閉題答案測試；若要可重現的乾淨案例，請在開始任何遠端寫入前，用完整標記的專用副本建立新活動。Q1開始後，讓第一組提交測試文字（例如 `=1+2`、中文／換行）、第二組稍後提交不同文字，確認 receiveRank=1 的實際答案。手動閉題。Q2可仍開放或無提交，作排除案例。
5. 閉題前及閉題後都確認原表未自動改值。老師按「寫回 Google Sheets」一次；等待「已讀回核對完成」及逐題「已核對」。PRECHECKING／WRITING／VERIFYING 或 HTTP 202／Google 2xx 均不是成功。只選當次快照已閉且有提交的題，無人與尚未閉題題目不寫。無符合項目應顯示「無可寫回答案」。
6. 在 Google Sheets 人工確認原動態答案格只有最快有效答案，`=1+2` 是字串而非公式；對照其他值、公式、整格格式、非答案局部格式、合併與結構未改。系統老師頁可刷新恢復操作；學生頁不得看到來源或寫回進度。寫回等待時仍可正常提交／閉題／下一題，但後來閉題不加入舊快照。
7. FAILED 若為明確未送出／明確拒絕，可修正權限或認證後重新人工操作；不要把 Google 失敗當本機老師 Session 過期。CONFLICT 停止操作、保留狀態及安全位置訊息。PENDING_VERIFICATION 或仍 running 時，**只用「重新取得寫回狀態」查本機狀態**，不要重送、不手改目標、不重啟企圖取消。US3尚無US4手動 reconcile／恢復功能；未知寫入可能仍在遠端執行，先回報人工審查。
8. 本輪不測完整重複／恢復流程。確認已成功且沒有 running／pending 後，未來重用需先手動還原標記或複製新範本，再建立新活動；沒有自動還原。不同第二份真表及完整異常／恢復驗收仍是後續任務。
9. 回報來源代稱、確認日期（區分實際測試時間）、題數／分頁、權限提示、實際逐題結果、未改區域比對及 PASS／FAIL／PENDING。可提供遮蔽畫面；不要傳 key、Token、實際 credential 路徑或真實學生答案。一次人工成功不等於兩份真表自動驗收通過。
