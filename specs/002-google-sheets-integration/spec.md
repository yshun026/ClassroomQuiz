## Clarifications

### Session 2026-11-18

- Q: 第一版遇到答案佔位符儲存格內含局部文字格式時應如何處理？ → A: A（使用者回覆 recommended）：讀取時拒絕含局部文字格式的答案格，指出位置，請老師整理範本後重試；一般整格字型、底色、框線仍須保留，非答案格的局部文字格式不受影響。
- Q: 若準備時已確認 Service Account 只能讀取來源或無權編輯答案格，是否允許開始搶答？ → A: A（使用者回覆 recommended）：已確認無寫入權時拒絕建立活動，提示修正分享或保護範圍；活動開始後才撤權則保留搶答結果，寫回時回報錯誤，不以寫入測試值檢查權限。
- Q: 若來源可讀、題目格式有效，但無法在不寫測試值的情況下確認答案格可編輯，是否允許建立活動？ → A: A（使用者回覆 recommended）：允許建立並顯示「寫入權限尚未確認」；老師仍須事先分享編輯權，讀取成功不等於可寫入保證，實際寫回仍須完整檢查並處理授權錯誤。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 老師以不同網址準備活動 (Priority: P1)

老師沿用管理密碼，設定組數並貼上已授權的 Google Sheets 網址；系統完整驗證所有支援分頁後建立活動，老師與學生不在系統登入 Google。

**Why this priority**: 正確來源、題數與位置是搶答及回填共同前提。

**Independent Test**: 不開始搶答，分別以兩份不同網址、分頁與格址的試算表驗證準備、拒絕與重試。

**Acceptance Scenarios**:

1. **Given** 老師已登入、組數有效、來源可讀且含跨表唯一連續 Q1..Q3，沒有已確認的寫入權限拒絕，**When** 貼入網址讀取並完成來源驗證，**Then** 不顯示 Google 登入，顯示來源名稱、三題與 Q1 WAITING；若不能以不修改內容的方式確認答案格可編輯，允許建立但明示「寫入權限尚未確認」，不將讀取成功稱為可寫入保證。
2. **Given** 新活動使用另一份已授權網址且標記位置不同，**When** 準備，**Then** 題數與位置依新來源決定，不沿用前一份 ID／格址。
3. **Given** 網址帶 gid 且其他分頁有標記，**When** 讀取，**Then** 掃描整份來源所有支援分頁，包含隱藏分頁，不限 gid；未納入的非支援分頁須列出。
4. **Given** 非合法網址、未授權／不存在來源、憑證不可用、讀取失敗，或已確認 Service Account 對原表／任一答案格無寫入權，**When** 準備，**Then** 顯示原因、保留有效組數、不建立部分活動；權限問題提示修正分享或保護範圍後重試，不能以寫測試值確認權限。
5. **Given** 缺號、跨表重複、Q0／Q01／q1、破括號、混字／前後空白／多標記、公式標記、無標記或答案佔位符儲存格含局部文字格式，**When** 讀取，**Then** 拒絕整份來源，對可定位問題指出表名、格址及題號，不允許開始；局部文字格式答案格須提示老師整理後重試，不自動移除格式。
6. **Given** 組數未設定／無效，或兩份來源同時讀取／讀取中更改組數，**When** 處理，**Then** 未具有效組數先拒絕來源讀取；準備互斥且忙碌操作拒絕，失敗釋放鎖。只有有效組數及來源完整驗證齊備才一次建立活動，不另存已驗證來源草稿或新增草稿狀態；活動建立後來源與組數不可替換。
7. **Given** 學生或未登入者，**When** 要求準備操作，**Then** 後端拒絕，不執行受保護的來源操作。

### User Story 2 - 保留既有公平搶答 (Priority: P1)

雲端讀取成功後，老師及學生沿用 001 的搶答流程，雲端等待不參與順位及閉題裁定。

**Why this priority**: 本次只替換 Guided Notes 流程，不能破壞已完成核心功能。

**Independent Test**: 已準備活動中，老師與至少三組完成多題流程、刷新／重連，並模擬雲端不可用。

**Acceptance Scenarios**:

1. **Given** Q1 WAITING，**When** 老師開始、多組提交及閉題，**Then** 後端依有效接收處理順序分配唯一連續順位，每組每題一筆；空白、重複、閉題後提交拒絕，不判答案對錯。
2. **Given** 尚未閉題，**When** 他組提交或執行雲端操作，**Then** 學生僅取得自己的當題資料，不取得他組答案／順位／提交狀態及全域計數；他組提交不使觀察組收到額外業務通知。
3. **Given** 非最後題已閉題，**When** 下一題，**Then** 僅到 WAITING 仍須手動開始；最後題閉題直接 COMPLETED、結果保留，已閉題不可重開。
4. **Given** 活動已準備成功，**When** Google 斷網或寫回等待，**Then** 已載入搶答仍可開始、提交、閉題與公布，順位及接受條件不變。
5. **Given** 正常本機連線，**When** 活動變更或有效提交，**Then** 沿用 001 的 2 秒同步、晚加入、身分恢復、同身分多頁籤與重連不重送規則。

### User Story 3 - 老師手動寫回閉題成功答案 (Priority: P1)

老師於任意已準備階段手動寫回，只回填同一結果快照中已閉題、有有效提交題目的最快答案，保護原表其他內容。

**Why this priority**: 直接寫回原 Guided Notes 是公告要求的主要變更。

**Independent Test**: 以包含未開始、搶答中、已閉題有答案及無人作答的活動快照，逐格比較原表與寫回結果。

**Acceptance Scenarios**:

1. **Given** 已閉題且有有效提交，**When** 老師手動寫回，**Then** 最小順位答案填入活動綁定原試算表的動態位置，不建立替代試算表、不下載 XLSX。
2. **Given** 未閉題或無人作答，**When** 寫回，**Then** 不更新該格；沒有任何符合題目時顯示無可寫回答案，不執行遠端寫入。
3. **Given** 目標仍為原始純文字標記，來源／位置核對通過，**When** 回填並讀回核對，**Then** 完整保留答案文字，包括 `=1+2`、空白、換行、中文與 Unicode，不轉成公式、數字或日期。
4. **Given** 原表有題目、非答案文字、公式、格式、合併及多分頁，**When** 回填，**Then** 只變更應填格的值，其他內容、公式定義、格式與結構不變；答案引起的公式重算不視為改寫公式。
5. **Given** 閉題與寫回競爭，**When** 快照先取得，**Then** 不包含稍後才閉題者；閉題先完成則可包含。不混用快照前後結果，不改活動階段、答案或順位。
6. **Given** 學生、失效身分、舊活動或另傳目標 ID／格址，**When** 要求寫回，**Then** 拒絕，以活動綁定來源與映射為準。

### User Story 4 - 安全處理重複、衝突與結果不明 (Priority: P1)

老師能辨識成功、無需更新、衝突、確定失敗與結果待核對，不因重複操作或回覆遺失覆蓋他人修改。

**Why this priority**: 雲端原表可被他人編輯，失敗回覆不代表遠端未寫入。

**Independent Test**: 受控修改目標、移動標記、撤權、斷網、回覆遺失及雙頁籤寫回，核對遠端與本機結果。

**Acceptance Scenarios**:

1. **Given** 本活動該題已核對成功，映射未變且現值仍為預期純文字答案，**When** 再寫回或驗證來源結構，**Then** 結合本活動 WritebackEvidence 辨識原標記已由答案取代，顯示已同步並略過該格，不誤判標記遺失；其他新閉題題目仍可處理。
2. **Given** 任一目標改成不同值、公式、空白，或表被刪除／位置、合併與標記映射不再可信，**When** 寫前核對，**Then** 顯示衝突位置與原因，本次尚未送出的更新全部停止，不移到另一格或強制覆蓋。
3. **Given** 首次寫回目標不是原標記、恰與答案相同，但無本活動成功或待核對依據，**When** 核對，**Then** 仍視為衝突，不以字串相同猜測先前成功。
4. **Given** 已送出操作但逾時／回覆遺失，**When** 無法確定遠端結果，**Then** 顯示結果待核對，保留原快照及目標，不宣稱未寫入、不立即盲目重送。
5. **Given** 待核對操作，**When** 老師再次手動處理，**Then** 先結合本活動原操作紀錄及既有 WritebackEvidence 核對來源結構，再讀回原操作全部目標：預期純文字答案為內容已核對、原標記為未完成、其他值為衝突；不得將紀錄可解釋的標記替換誤判為遺失。讀取失敗保持待核對，有衝突則停止後續更新，無衝突才可寫仍為原標記的目標。
6. **Given** 重複點擊或多老師頁籤，**When** 操作執行中或待核對，**Then** 同一活動不並行寫回；待核對先處理原快照，再允許新操作，舊快照不得晚到覆蓋新結果。
7. **Given** 權限、網路或配額失敗，**When** 處理，**Then** 提示可重試或需修正授權並保留搶答資料；確知未送出／遠端明確拒絕可標失敗，可能已送達則待核對，不以整表回滾修復。
8. **Given** 原表已回填且後端重啟，**When** 再作新來源，**Then** 仍要求完整 Q1..QN；缺標記則拒絕，提示先還原標記或使用重新複製且標記完整的範本，不把答案猜為標記。

### Edge Cases

- 合併格只計左上主格一次；公式結果顯示 `{{Q1}}` 仍不是有效純文字標記。
- 第一版答案佔位符儲存格不得含局部文字格式（例如部分字元加粗、變色或局部超連結）。讀取時發現即拒絕整份來源並指出位置，不自動清除或簡化格式。一般整格字型、底色、框線不屬此限制；非答案格的局部文字格式必須保留。寫前若答案格被新增局部文字格式，視為衝突，停止尚未送出的更新。
- 支援分頁為一般可讀寫格線工作表（GRID），含隱藏分頁。非 GRID 分頁須明示未納入；所有題目須位於支援範圍，不能宣稱其他類型均受支援。
- 表名含空白／單引號、分頁更名或重新排序，不可寫錯表；不能證明映射仍有效則拒絕。
- 匯入後插刪列欄、新增／刪除／移動題目，不可靜默改題數或重新綁題；後續結構／位置／標記核對須以匯入映射，結合本活動 WritebackEvidence 與待核對操作中記錄的預期替換值判定。可由紀錄解釋的答案取代標記不是缺號或遺失，不得重新要求全表仍含完整原標記；無依據的替換、位置／結構變更或值與型別不符仍為衝突。
- 準備時已確認來源唯讀或任一答案格不可編輯，拒絕建立活動並提示修正分享／保護範圍；活動開始後才撤權，仍保留搶答與結果，寫回時回報授權錯誤。不得繞過授權或以寫測試值檢查權限；準備時檢查通過不保證權限之後不變。
- 來源可讀且其他驗證通過，但無法以不修改內容的方式確認寫入權限，允許建立活動並持續於老師端顯示「寫入權限尚未確認」；不得顯示已取得寫入保證。已確認無權限與尚未確認必須分開處理；寫回結果另依當次核對決定。
- 讀回部分為答案、部分為原標記，須逐題顯示，不誤報整批成功或清除已寫答案。
- 答案可恰為 `{{Q1}}` 等標記。恢復須依本活動操作紀錄，不只重新全表掃描；無法證明位置安全則停止。若預期答案與原標記相同，確認值與型別吻合即可視為內容已同步，不宣稱可證明曾發生寫入。
- 超過遠端可表示範圍或含無法可靠保存字元時明確失敗，不截斷／替換答案；不修改既有搶答答案接受規則。
- 瀏覽器中斷／換 Session 不代表遠端取消；有效老師重新取得後端操作狀態，不自動重送。
- 後端重啟允許清空本機資料，雲端已寫值不回滾，不承諾跨重啟恢復待核對操作。
- 第一版要求活動期間外部編輯者不改題目結構與答案格，含檢查至寫入期間；這是使用約定，不是 Google 鎖定保證，仍須每次檢查衝突。

## Requirements *(mandatory)*

### Functional Requirements

FR 編號屬於 002，不覆蓋 001 同號需求。Google Sheets API／Service Account 為使用者指定約束；套件、認證載入、HTTP 合約與保護方法留待 Plan。

- **FR-001**: 正式流程改為 Google Sheets API 直接讀取及寫回同一原表，不再以 Excel 匯入／匯出作正式操作，保留 001 歷史。
- **FR-002**: 優先由後端 Service Account 存取已授權來源，老師與學生不在系統登入 Google；沿用管理密碼及免註冊學生。不可行須回報並審查，不默改 OAuth 登入。
- **FR-003**: 老師可為不同活動貼不同合法 Sheets 網址，不寫死 ID／格址，不讀任意外部網址。首版接受 HTTPS `docs.google.com/spreadsheets/d/<id>/...`，不支援短網址／發佈檢視連結。
- **FR-004**: 預設掃描全部支援分頁，含隱藏分頁、不受 gid 限縮；列出未納入分頁。題數依有效標記，不解析題目敘述、不新增題組。
- **FR-005**: 沿用整格純文字 `{{Q1}}` 起唯一連續安全正整數題號驗證；非法、缺號、重複、公式、混字／空白／多標記拒絕；合併格只取主格。答案佔位符儲存格含局部文字格式時，讀取即拒絕整份來源並指出位置，要求人工整理後重試，不自動刪除格式。
- **FR-006**: 先確認組數有效才讀取來源，全部來源驗證成功後一次建 Q1 WAITING；若已確認 Service Account 對原表或任一答案格無寫入權，須拒絕建立並提示修正分享／保護範圍，不以寫測試值驗權。若來源可讀且其他驗證通過，唯寫入權限無法以不修改內容的方式確認，允許建立但老師端須明示「寫入權限尚未確認」，不得將可讀視為可寫保證。不另存已驗證來源草稿或新增草稿狀態。準備互斥，失敗不留半場活動、保留有效組數且可重試；建立後鎖定來源與組數。
- **FR-007**: 準備及寫回均由後端驗老師權限與適用活動，目標由活動來源及動態映射取得，拒絕學生、失效／舊活動與任意目標替換。
- **FR-008**: 保留 001 排序、每組單筆、提交／閉題一致順序、四階段、最後題完成、隔離、2 秒同步、晚加入及恢復；雲端等待不參與提交／閉題裁定。
- **FR-009**: 四個已準備階段均可由老師手動寫回，不因提交／閉題／重連自動寫；無符合題目不發起遠端寫入。
- **FR-010**: 使用同一時間點不可變閉題快照，只取有提交題目的最小順位文字；未閉題／無人不填，不改活動階段、題號、答案、順位或搶答版本。
- **FR-011**: 寫前驗原試算表及工作表身分、動態位置、合併關係與原標記／本活動已核對預期值。重複寫回及結構驗證必須結合匯入映射、本活動 WritebackEvidence 與待核對原操作紀錄，接受紀錄可解釋的答案取代原標記，不可因該標記已被取代而誤報遺失；未寫入且無紀錄可解釋者仍須為原標記。不只靠表名、固定座標或現值等於答案推定安全。
- **FR-012**: 全部待寫格前置核對通過才送本次更新；偵測結構、標記或值衝突即停止全部尚未送出更新，指出安全位置／原因，不強制覆蓋或重新綁題。
- **FR-013**: 只改符合條件的答案格值，保留非答案內容、公式定義、格式與結構，包含一般整格格式與非答案格的局部文字格式；答案格的局部文字格式依 FR-005 在讀取時拒絕，若寫前才新增則按 FR-012 衝突停止，不靜默移除。完整文字不轉公式／數字／日期，無法表示則明確失敗。
- **FR-014**: 成功須以讀回目標核對為依據；區分逐題已核對／略過／待核對／衝突／未處理，不把送出等同成功或部分等同整批成功。
- **FR-015**: 重複操作只略過有本活動成功依據、映射一致、現值及型別仍吻合的格；改值則衝突，不跨活動或重啟沿用不存在紀錄。
- **FR-016**: 可能已送達而結果不明時保留原操作快照及逐題預期值，標待核對；手動重試先依 US4.5 讀回原操作全部目標，不盲重送／回滾。
- **FR-017**: 同活動寫回互斥，執行中回忙碌，待核對先恢復原操作，禁止舊快照晚到覆新結果；外部故障不影響本機搶答及已公布結果。
- **FR-018**: 網址、認證、無權／不可存取、唯讀／保護格、格式、配額、遠端錯誤、衝突及結果不明須有不洩密的可理解提示；不能區分不存在與無權時不虛構原因。準備時已知無寫入權依 FR-006 拒絕；活動開始後撤權不清除搶答結果，寫回時回報錯誤，修正授權後依原操作狀態安全重試。
- **FR-019**: 私鑰、存取 Token、管理密碼與機敏回應不得出現在前端、GitHub 或證據；真實憑證僅由後端於 repository 外受控取得，本階段不建憑證。
- **FR-020**: 沿用本機單活動及程序生命週期；重啟可清本機、不回滾雲端。重用需先還原完整標記或自行複製範本，不自動還原／複製或猜測已填答案。後續本 Feature 的 quickstart.md 必須說明此重用步驟，以及同活動重複寫回與新活動完整標記驗證的區別；Specify 階段未建立 quickstart.md；由後續 Plan 產生。
- **FR-021**: 保存自動、人工、兩份真實授權來源及三圖一致性證據，涵蓋多組搶答與錯誤分支；未執行須標示，不以 001 通過數字宣稱新功能通過。
